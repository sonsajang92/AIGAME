# Tichu Clone Starter

비전공자도 단계적으로 실행하고 고칠 수 있게 만든 티츄(Tichu) 실시간 웹게임 프로젝트입니다.

## 현재 목표

1. UI 복구 및 레이아웃 정상화
2. 이벤트 계약과 서버 검증 최소 일관화
3. 패스, 트릭, 라운드, 점수, 선언 규칙을 단계적으로 확장
4. PWA와 모바일 클라이언트 전환을 위한 문서 정리

## 포함 기능

- 방 입장
- 4인 입장 시 카드 배분
- 실시간 채팅
- 턴 기반 카드 1장 내기
- 패스와 트릭 종료
- 라운드 종료와 기본 점수 집계
- 티츄/더블티츄 선언 점수

현재 코드는 학습용 MVP입니다. 정식 티츄 규칙은 이후 단계에서 `game-logic.js`, `server.js`, `docs/socket-events-v1.md`를 함께 맞추며 확장합니다.

## 기술 스택

- Backend: Node.js + Express + Socket.IO
- Frontend: Vanilla HTML/CSS/JS + Socket.IO client

## 실행 명령

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:3000`에 접속합니다.

## 검증 명령

```bash
node --check server.js
node --check public/app.js
```

충돌마커 검사는 아래 명령을 실행합니다. 아무 결과도 나오지 않아야 정상입니다.

```bash
git grep -n -E '^(<{7}|={7}|>{7})'
```

## 카드 점수표

| 카드 | 점수 |
|---|---:|
| 5 | +5 |
| 10 | +10 |
| K | +10 |
| Dragon | +25 |
| Phoenix | -25 |
| 그 외 카드 | 0 |

## 선언 규칙

| 선언 타입 | 성공 조건 | 성공 시 | 실패 시 |
|---|---|---:|---:|
| `tichu` | 선언한 플레이어가 라운드 1등 | +100점 | -100점 |
| `double_tichu` | 선언한 플레이어 팀이 라운드 1, 2등 | +200점 | -200점 |

라운드 종료 시 선언 결과는 `round_end.scoringNotes`에 포함되고, 점수는 `roundDelta`와 누적 `teamScores`에 반영됩니다.

## PWA 메모

- `public/manifest.json`으로 앱 이름, 아이콘, 테마 정보를 제공할 수 있습니다.
- `public/sw.js` 서비스워커를 등록하면 설치형 웹앱과 오프라인 캐시를 확장할 수 있습니다.
- 서비스워커를 추가할 때는 캐시 버전 갱신, 구 캐시 제거, 오프라인 fallback을 함께 점검합니다.

```js
if ('serviceWorker' in navigator) {
  window.addEventListener('load', () => {
    navigator.serviceWorker.register('/sw.js');
  });
}
```

## STEP A 완료 기준

- 서버가 `npm run dev`로 실행된다.
- 브라우저에서 로비, 테이블, 플레이어, 내 카드, 채팅 영역이 겹치지 않고 보인다.
- 방 ID와 닉네임 입력 후 입장 버튼을 누르면 플레이어 목록에 내가 표시된다.
- 브라우저 4개를 같은 방으로 열면 손패가 배분된다.
- 내 턴에 카드 버튼을 누르면 중앙 테이블 카드가 갱신된다.

## STEP B 완료 기준

- 클라이언트 입장 이벤트가 `join_room { roomId, playerName }`로 동작한다.
- 채팅 이벤트가 `chat_send { message }`, `chat_new { playerName, message, ts }`로 동작한다.
- 카드 제출 이벤트가 `play_cards { cards }`로 동작한다.
- 패스 이벤트가 `pass_turn {}`로 동작한다.
- 서버의 실패 응답은 `action_error { code, message }`로만 표시된다.
- 코드와 payload에서는 `playerName`만 사용한다.

## STEP C 완료 기준

- 새 트릭을 시작하는 플레이어는 패스할 수 없고 카드를 내야 한다.
- 누군가 카드를 낸 뒤 다른 3명이 연속 패스하면 트릭이 종료된다.
- 트릭 종료 시 테이블 카드가 비워지고 채팅 로그에 승자가 표시된다.
- 다음 턴은 마지막으로 카드를 낸 트릭 승자에게 돌아간다.
- 아직 점수 계산과 라운드 종료는 하지 않는다.

## STEP D 완료 기준

- 누군가 마지막 손패를 내면 서버가 라운드를 `ended` 상태로 바꾼다.
- 클라이언트는 `round_end` 이벤트를 받아 테이블에 라운드 종료 문구를 표시한다.
- 라운드 종료 후 카드 제출과 패스가 비활성화된다.
- `teamScores`, `roundDelta`는 아직 0점 뼈대 값으로 유지한다.
- 실제 티츄 점수 계산은 다음 단계에서 구현한다.

## STEP E 완료 기준

- 트릭을 가져간 플레이어에게 해당 트릭 카드가 `capturedCards`로 누적된다.
- 라운드 종료 시 `playerSummaries`에 남은 카드 수와 획득 카드 점수 요약이 포함된다.
- 기본 점수 카드 `5`, `10`, `K`가 집계된다.
- 채팅 로그에 팀별 임시 점수와 플레이어별 남은 카드 수가 표시된다.
- 티츄 선언 점수, 특수 카드, 남은 손패 점수 이동은 아직 구현하지 않는다.

## STEP F 완료 기준

- 손패를 모두 낸 플레이어는 이후 턴에서 제외된다.
- 같은 팀 두 명이 먼저 나가면 해당 팀이 200점을 얻고 라운드가 종료된다.
- 일반 흐름에서는 3명이 나갔을 때 라운드가 종료된다.
- 마지막 남은 플레이어의 획득 카드는 첫 완주자에게 이동한다.
- 마지막 남은 플레이어의 남은 손패 점수는 상대 팀에 더해진다.
- 채팅 로그에 이번 라운드 점수와 누적 팀 점수가 표시된다.

## STEP G 완료 기준

- 내 카드 영역에서 `티츄`, `더블` 선언 버튼을 사용할 수 있다.
- 한 플레이어는 한 라운드에 한 번만 선언할 수 있다.
- 티츄 선언자가 1등이면 +100점, 아니면 -100점으로 반영된다.
- 더블티츄 선언자 팀이 1, 2등이면 +200점, 아니면 -200점으로 반영된다.
- 라운드 종료 채팅 로그에 선언 점수 결과가 표시된다.
